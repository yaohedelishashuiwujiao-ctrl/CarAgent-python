# 简历 Agent 部分：六个核心维度母版

> 本版本暂不限制篇幅，用六个一级维度重组 Agent 项目。后续简历精简以此为基准，每个维度至少保留一个核心判断和一个关键机制。

## 竞品数据智能分析 Agent

针对传统 RAG 只能基于文档片段回答问题、难以完成结构化取数、统计分析、多源验证和可交付任务的问题，依托底盘竞品数据平台的 3 万余条结构化数据及数百份调研报告、拆解报告和用户手册，从 0 到 1 构建受控任务执行型通用 Agent 系统，打通从用户问题、任务调度、自主规划、工具执行、证据验证到结果交付的完整链路。

### 1. 整体框架

- 将系统划分为前端交互、异步任务、准入与调度、Agent 决策、工具执行、证据与契约、持久化与观测七层，形成“用户问题→Job 创建→路由估算→公平调度→Agent 循环→工具调用→证据回写→完成条件校验→SSE 交付”主链路。
- 用户请求首先转换为携带身份、会话、数据范围、允许工具和输出要求的异步 Job，调度层负责准入、排队和执行所有权，Agent 层只负责任务决策，避免将高并发、权限和业务推理混在同一循环中。
- 工具结果同时进入两条链路：向 Agent 返回紧凑观察用于继续决策，向证据层写入完整结果、证据哈希、引用、结论和审计信息；最终结果必须同时满足任务完成条件、证据要求和输出格式要求，不以“模型已生成文字”作为任务完成标准。
- 记录任务路由、模型调用、Token、工具 attempt、候选工具变化、耗时、异常、证据、结论及数据访问审计，实现从最终回答反查到路由决策、工具输入和原始数据来源。

### 2. 并发能力

- 将长耗时 Agent 任务封装为异步 Job，基于 Redis Streams 与持久化 Outbox 解耦 API 接入和 Worker 执行，前端通过 SSE 持续接收 queued、admitted、running、tool use、telemetry 和 final 事件，并支持 `Last-Event-ID` 断线续传。
- 设计成本感知 DRR 公平调度，将路由估算的任务成本纳入队列积分消耗，保证低成本任务吞吐，同时防止大任务或单一用户长期占用执行资源。
- 将模型、SQL、RAG、Web、通用工具和文件产物划分为独立有界资源池，通过分级 semaphore、有界排队、快速拒绝和背压防止单类依赖耗尽系统资源。工具层对同类只读请求自动组成 Batch，对无依赖、幂等且无副作用的工具并行执行，对会话状态和文件产物类操作隔离串行。
- 通过幂等键、会话锁、心跳租约、execution/fencing token 和状态迁移校验保证任务一致性：同一会话不被多个 Worker 并发污染，超时 Worker 恢复后不能覆盖新执行者状态，任务取消、重试和故障恢复不会将旧结果误写为成功。

### 3. 安全能力

- 将用户身份、角色、数据范围和允许工具快照绑定到 Job，后端向 Agent 执行链签发短时 HMAC Token，校验签名、issuer、audience、session、过期时间并防止重放；结构化查询、RAG 和所有工具执行继承同一权限边界。
- 生产模式仅加载通过安全审核的工具，默认移除 Bash、任意文件写入、未授权子任务和其他高风险能力。未授权工具既不允许执行，也不会出现在候选工具和 ToolSearch 结果中，防止工具能力、参数 Schema 和数据边界泄漏。
- 工具真实执行前统一进行 Eligibility、allowlist、JSON Schema、参数边界、数据范围和输出契约预检，对注定失败或越权的调用在进入数据源前结构化拒绝。
- 通用 SQL 采用只读账号、SQL AST、单语句限制、表/字段白名单、EXPLAIN 成本门禁、执行超时及结果行数/字节限制；Web 抓取仅允许 HTTPS 白名单域名，并阻断私网地址、非法重定向和超大响应；RAG 只检索已发布且通过版本、密级和 ACL 校验的文档。
- 将安全从“调用前拦截”延伸到“结果可信”：为 SQL、RAG 和 Web 结果计算 evidence hash，由系统统一分配引用编号，将最终回答拆分为原子结论并建立 claim→citation 映射，检查非法引用、数值/单位不一致、支持度不足和无证据结论，对高风险不一致执行修复、降级、拒答或人工复核提示。

### 4. Agent 循环

- 将用户请求转换为包含任务类型、目标对象、所需证据、输出形式和完成标准的任务契约，通过“制定计划→调用工具→观察结果→更新状态→判断进展→继续/重规划/终止”循环执行复杂任务。
- 显式维护任务计划、已完成步骤、执行动作、失败路径、证据账本、需求满足度和重规划信号。每次工具调用后不仅向模型返回文本，还返回 outcome status、reason code、retryable、coverage boundary 和新增证据，使 Agent 能区分无数据、输入错误、权限拒绝、暂时故障和能力缺失。
- 当出现无数据、覆盖不足、依赖故障、权限受限或输出要求未满足时，按结构化原因扩展回退工具、改写查询、调整计划或进入边界化交付；当连续调用产生新证据时允许继续执行，而不是使用固定小轮次粗暴截断任务。
- 完成阶段同时校验任务契约、证据覆盖和输出契约。对文字、结构化 JSON、图表和 PPTX 等不同交付形式分别验证；用户明确要求文件时，纯文字回答不能被标记为成功，未满足契约的 final 事件也不会提前发布到前端。

### 5. 工具调用机制与 RAG 混合检索

- 建设结构化数据查询、业务字段目录、受控统计、只读 SQL、知识检索、网页检索/抓取、图表和文件产物等工具体系，为工具统一定义能力边界、JSON Schema、读写属性、幂等性、副作用、超时、重试条件、资源池和结果大小限制。
- 根据任务路由、权限、数据范围、工具配置和依赖可用性动态收窄候选工具，首轮仅暴露主能力，在无数据、覆盖不足、能力缺失或交付契约未满足时再扩展回退工具。通过 ToolSearch 按能力、动作、对象、输入/输出模式和正反例渐进式发现工具，减少无关 Tool Schema 对工具选择和上下文的干扰。
- 工具调度前统一完成名称归一化、Schema/参数/权限预检、调用去重和依赖分析，再决定 Batch、并行或串行。执行失败后，仅对幂等、明确可重试且命中暂时故障白名单的调用重试；输入错误、权限拒绝、覆盖不足和非幂等产物不盲目重试。
- 结构化数据链路以平台数据库作为参数、统计和对比结论的事实源，业务目录先返回字段含义、单位、覆盖车型数和有效值数，Agent 再决定使用专用属性/统计工具还是通用 SQL，减少无目的 Schema 探索。
- 非结构化知识链路面向 PDF、PPT、Word、OCR 文本、表格及用户手册，采用 BM25 与字符级 TF-IDF 双路召回、RRF 融合排序，并预留 Dense 检索；结合品牌、车型、年款、系统、文档类型、版本、发布状态、密级和 ACL 进行元数据过滤，通过 Search/Fetch 两阶段检索先定位高相关片段，再按 chunk/document 精确获取完整证据，减少无关文本进入模型上下文。
- RAG 质量不只通过最终回答判断：检索层使用 Recall@K 和 MRR 评估召回与排序，回答层检查引用完整性、结论支持度和数值一致性；结构化数据问题优先使用 SQL/业务工具证据，设计背景、功能说明和研究资料使用 RAG 证据，避免将文档检索当作所有事实的唯一来源。

### 6. 成本控制

- 在 Job 创建前估算任务类型和执行成本，在 Agent 执行前通过零模型成本 L0 路由识别高频确定性任务，再按参数查询、手册问答、趋势分析、文件产物和通用任务划分预算等级。
- 路由结果不只选择模型，而是统一决定执行路径、模型档位、主/回退工具集、预期证据类型、最大模型轮次、最大工具调用和输入 Token 预算。高置信的单车属性、字段目录和受控统计问题直达确定性工具，不调用模型进行工具规划；复杂任务才启用多轮 Agent 循环。
- 每轮记录 Token、模型轮次、工具请求/执行/拒绝、结果新颖度和证据增量，通过重复调用检测、重复结果检测、连续无进展和低收益终止防止工具空转；对持续产生新证据的长任务保留执行空间，不以过小的固定轮次牺牲任务完成率。
- 在每次模型调用前统一计算 System Prompt、Tool Schema、对话历史、工具结果和输出预留的 Token 占用；超过软阈值时将旧工具结果外置为证据句柄，超过硬阈值时以完整 tool-call/tool-result 为原子单元裁剪，保留用户约束、任务状态、关键数据和引用关系。
- 通过渐进式工具暴露减少 Tool Schema Token，通过 Search/Fetch 两阶段检索减少无关文档上下文，通过结构化工具直达减少 SQL 探索轮次，通过精确重试避免对不可恢复错误反复消耗资源，将成本控制贯穿路由、上下文、工具和任务调度全链路。

## 六个维度的一句话价值

1. **整体框架：** 把自然语言问题变成可调度、可执行、可验收、可追溯的任务。
2. **并发能力：** 让长任务和多用户可以稳定共存，而不是只能完成单用户 Demo。
3. **安全能力：** 同时控制“能调什么、能读什么、能写什么、最终能说什么”。
4. **Agent 循环：** 让模型根据真实执行结果持续调整计划，直到达成完成条件。
5. **工具与 RAG：** 让 Agent 既能对结构化数据行动，又能从非结构化知识中取证，并对工具选择和执行质量负责。
6. **成本控制：** 让不同复杂度的任务使用与其价值匹配的模型、工具、上下文和调度资源。
