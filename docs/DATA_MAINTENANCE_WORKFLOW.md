# 数据维护流程设计

## 目标

平台要让数据维护员能够在不修改数据库表结构的前提下，维护汽车底盘竞品数据。

完整闭环：

```text
定义实体类型
  -> 定义实体属性
  -> 创建整车实例
  -> 自动生成四大虚拟系统
  -> 添加零部件实例
  -> 填写/导入属性值
  -> 查询、导出、可视化、AI 分析
```

## 核心概念

### 实体类型

实体类型是数据字典的核心，例如：

- 整车
- 左前上摆臂
- 前副车架
- 制动盘
- 转向节
- 半轴

实体类型有自己的属性定义。

### 虚拟系统

四大系统是标准维度，不作为普通实体类型管理：

- 悬架系统
- 制动系统
- 转向系统
- 动力系统

创建整车实例后，平台自动生成四个系统 profile。

### 实例数据

实例是具体数据：

- 小鹏 X9 是整车实例。
- 小鹏 X9 左前上摆臂是零部件实例。

## 用户操作流程

### 1. 管理字典

管理员或数据负责人维护基础字典：

- 实体类型字典
- 虚拟系统字典
- 属性字段字典
- 枚举选项字典
- 单位字典
- 导入模板字典

### 2. 创建零部件实体类型

用户新增零部件实体类型时，需要填写：

- 实体名称：上控制臂/上摆臂
- 实体编码：upper_control_arm
- 实体分类：零部件
- 默认系统：悬架系统
- 描述

新增后可以为该实体类型配置属性：

- 安装位置
- 重量
- 材料
- 尺寸
- 工艺
- 供应商
- 图片
- 备注

### 3. 创建整车实例

用户新增车型时，需要填写：

- 整车编码
- 车型名称
- 品牌
- 年款
- 车身尺寸
- 轴距
- 整备质量
- 多视角图片

创建成功后，平台自动生成：

```text
小鹏 X9
  ├─ 悬架系统
  ├─ 制动系统
  ├─ 转向系统
  └─ 动力系统
```

### 4. 添加零部件实例

在整车结构树中选择系统节点后添加零部件：

- 选择零部件实体类型
- 自动带出默认系统
- 填写零部件实例编码
- 填写零部件实例名称
- 填写该实体类型对应的动态属性值

例如：

```text
整车实例：小鹏 X9
系统节点：悬架系统
零部件实体类型：左前上摆臂
零部件实例：小鹏 X9 左前上摆臂
```

## 数据类型

动态属性支持：

| 类型 | 用途 |
|---|---|
| text | 短文本，如品牌、材料 |
| long_text | 长文本，如结构说明 |
| number | 数字，如重量、长度 |
| integer | 整数，如孔数、数量 |
| enum | 单选枚举，如材料类别 |
| multi_enum | 多选枚举，如工艺标签 |
| date | 日期 |
| datetime | 时间 |
| boolean | 是否项 |
| image | 图片 |
| file | 附件 |
| json | 复杂结构 |
| relation | 关联其他实例 |

## 导入导出原则

导入导出不直接暴露数据库 ID 给普通用户，但入库时必须解析成 ID 关联。

用户侧模板使用：

- code
- name
- system_code
- entity_type_code

系统入库时转换为：

- vehicle_instance_id
- system_id
- entity_type_id
- attribute_id

## 错误处理

导入时必须校验：

- 必填字段是否缺失
- 编码是否重复
- system_code 是否存在
- entity_type_code 是否存在
- 动态字段是否存在
- 字段类型是否匹配
- 枚举值是否合法
- 数值单位是否匹配

错误结果应支持下载错误文件，方便数据维护员修正后重新导入。
