# Agentic RAG Knowledge Tools

The platform RAG stack is implemented as a LlamaIndex-based Agentic Hybrid RAG
service.  The agent still calls `KnowledgeSearch` and `KnowledgeFetch`, but the
retrieval implementation behind those tools is no longer a local sparse
baseline.

## Runtime Shape

```text
Agent loop
  -> KnowledgeSearch / KnowledgeFetch tool schemas
  -> Platform /api/rag/*
  -> LlamaIndex ingestion and retrieval layer
  -> Milvus dense vector index
  -> OpenSearch BM25 inverted index
  -> RRF fusion
  -> bge-reranker-base cross-encoder rerank
  -> cited chunks returned to the agent
```

## Chunking

Document ingestion keeps source metadata and uses LlamaIndex
`SentenceSplitter` for semantic token-window chunking:

```env
RAG_CHUNK_SIZE=1024
RAG_CHUNK_OVERLAP=150
```

Every node is indexed with metadata such as `chunk_id`, `document_id`,
`dataset_id`, `title`, `source`, `brand`, `model`, `year`, `source_type`,
`document_version`, `classification`, and `acl`.  Table-aware and
section-aware parsing should feed these metadata fields before indexing.

The current local index contains 500 documents and 12,120 chunks:

- 158 vehicle manual documents.
- 3 repair documents.
- 5 industry / policy report documents.
- 334 automotive arXiv research papers from the pre-parsed PDF corpus.

## Indexing

The index is intentionally hybrid:

- Milvus stores dense vectors generated by the configured embedding provider.
  The default provider is local `BAAI/bge-small-zh-v1.5`; production can also use an
  OpenAI-compatible embedding API.
- OpenSearch stores full chunk text and metadata for BM25 retrieval.
- Search always performs dense retrieval and BM25 retrieval, then fuses ranks
  with RRF.
- The fused candidates are reranked by `BAAI/bge-reranker-base`.

Default configuration:

```env
RAG_PROVIDER=llamaindex-agentic-rag
RAG_EMBEDDING_PROVIDER=huggingface
RAG_EMBEDDING_MODEL=BAAI/bge-small-zh-v1.5
RAG_EMBEDDING_DIM=512
RAG_EMBED_BATCH_SIZE=32
RAG_PRECHUNKED_PDF_MAX_DOCUMENTS=334
RAG_RERANK_MODEL=BAAI/bge-reranker-base
RAG_RERANK_MAX_LENGTH=512
RAG_DENSE_TOP_K=30
RAG_SPARSE_TOP_K=30
RAG_RERANK_TOP_N=10
RAG_MILVUS_URI=http://127.0.0.1:19530
RAG_MILVUS_COLLECTION=subjects_agent_chunks
RAG_OPENSEARCH_URL=http://127.0.0.1:9200
RAG_OPENSEARCH_INDEX=subjects-agent-chunks
```

For an embedding API, configure:

```env
RAG_EMBEDDING_PROVIDER=openai-compatible
RAG_EMBEDDING_MODEL=<provider embedding model>
RAG_EMBEDDING_API_KEY=...
RAG_EMBEDDING_API_BASE=https://...
RAG_EMBEDDING_DIM=<provider dimension>
```

Local infrastructure is defined in `docker-compose.rag.yml`.

## Tool Contract

`KnowledgeSearch` calls `POST /api/rag/search` and returns ranked chunks with
scores, metadata, and citation handles.  `KnowledgeFetch` calls
`GET /api/rag/chunks/{chunk_id}` to retrieve the full chunk and neighboring
context.

The agent should use this before web search for internal documents, vehicle
manuals, repair material, reports, market research, product facts, and any
claim that needs private-source evidence.
