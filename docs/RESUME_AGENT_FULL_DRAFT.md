# 简历 Agent 部分完整母版

> 本文档不考虑简历页数和单条长度，用于完整保留 Agent 系统的业务定位、架构链路、核心机制、创新点和验证结果。后续只在此基础上合并和精简，不直接删除关键能力。

## 竞品数据智能分析 Agent

针对传统 RAG 只能基于文档片段回答问题、难以完成结构化取数、统计分析、多源验证和文件交付的问题，依托底盘竞品数据平台的 3 万余条结构化数据及数百份调研报告、拆解报告和用户手册，从 0 到 1 构建受控任务执行型通用 Agent 系统。系统能够将用户目标转化为可路由、可规划、可调度、可验收的执行任务，自主组合数据查询、统计分析、RAG、外部检索及产物生成工具，完成从问题输入到证据化结果交付的完整闭环。

- **端到端 Agent 执行闭环：** 设计“用户问题—任务理解—完成标准识别—任务路由—计划制定—工具调用—结果观察—状态更新—动态重规划—输出验收—前端交付”主链路。Agent 不以生成文字为完成标准，而是持续追踪任务状态、证据覆盖和显式交付要求，只有满足任务契约和输出契约才能结束。

- **任务理解、规划与重规划：** 将用户问题抽象为包含任务类型、目标对象、所需证据、输出形式和完成标准的任务。通过显式计划管理分解多步任务，记录已执行动作、工具结果、失败路径、证据增量和完成进度；当出现无数据、能力不足、权限受限、依赖失败或产物未完成时，根据结构化结果进行重规划、工具切换、能力降级或明确终止。

- **分层路由与成本控制：** 构建零模型成本的 L0 快速路由和面向参数查询、手册问答、趋势分析、产物生成及通用任务的分层路由策略。路由结果统一决定执行路径、模型档位、候选工具、证据类型、最大模型轮次、最大工具调用和 Token 预算；高置信参数查询直达确定性工具，不消耗模型进行工具规划，复杂任务才进入多轮决策。运行中持续记录 Token、模型轮次、工具请求/执行/拒绝和证据增量，通过重复调用检测、连续无进展检测与低收益终止抑制工具空转和无效模型消耗。

- **自动上下文工程：** 在每次模型调用前统一计算 System Prompt、Tool Schema、对话历史、工具结果和输出预留的 Token 占用。超过软阈值时将较早的大体量工具结果外置为可追溯证据句柄，保留用户约束、任务状态、关键数据和引用关系；超过硬阈值时以完整 tool-call/tool-result 为原子单元裁剪，避免破坏工具调用语义，同时记录压缩快照与前后 Token 变化。

- **结构化数据分析：** 将竞品数据平台作为车型参数、字段定义、数值统计和对比结论的事实来源，建设业务字段目录、动态属性查询、受控统计和通用只读 SQL 工具，支持按车型、年款、底盘系统、零部件和属性进行筛选、聚合、覆盖分析和多车对比。业务目录先返回字段含义、单位、覆盖车型数和有效值数，Agent 再决定使用专用查询还是通用 SQL，减少无目的 Schema 探索和无效查询。

- **混合检索 RAG：** 面向 PDF、PPT、Word、OCR 文本、表格及用户手册建设知识检索链路，采用 BM25 与字符级 TF-IDF 双路召回，通过 RRF 融合排序，并预留 Dense 检索能力；结合品牌、车型、年款、底盘系统、文档类型、发布状态、版本、密级和 ACL 进行元数据过滤。将检索拆分为 Search/Fetch 两阶段：先返回高相关片段和文档标识，再按 chunk/document 精确获取完整证据，减少大段无关文本进入模型上下文。检索评测覆盖 Recall@K 与 MRR，生产检索仅允许已发布且通过数据权限校验的文档。

- **动态工具发现与调用准确性：** 根据任务路由、用户权限、数据范围、工具配置和依赖可用性每轮收窄候选工具，首轮仅暴露主能力，只有出现无数据、覆盖不足、依赖失败或交付契约未满足时才扩展回退能力。支持通过 ToolSearch 按能力、动作、对象、输入/输出模式和正反例渐进式发现工具，避免一次性向模型暴露所有 Tool Schema 导致选择干扰和 Token 浪费。

- **工具契约、预检与执行安全：** 为工具统一定义能力边界、JSON Schema、读写属性、幂等性、副作用、超时、重试条件、并发资源池和结果大小限制。真实执行前统一完成 Eligibility、权限、数据范围、Schema、参数边界和输出契约预检，对注定失败的调用直接结构化拒绝。通用 SQL 采用只读账号、SQL AST、单语句限制、表/字段白名单、EXPLAIN 成本门禁、超时和结果行/字节限制；外部网页仅允许 HTTPS 白名单域名，并阻断私网地址、非法重定向和超大响应。

- **工具批处理、并行与故障处理：** 工具调度前先完成名称归一化、参数预检、调用去重和依赖分析，对同类只读调用优先组合为 Batch，对无依赖、只读、幂等且无副作用的工具并行执行，对会话状态和文件产物类工具隔离串行。模型、SQL、RAG、Web 和产物工具使用独立有界资源池；仅对明确可重试且幂等的暂时性失败执行精确重试，对输入错误、权限拒绝、数据覆盖不足和非幂等操作不盲目重试。每次调用统一返回 outcome status、reason code、retryable、证据和覆盖边界，为 Agent 的下一步决策提供结构化观察。

- **证据链、引用与幻觉控制：** 从结构化查询快照、RAG 文档片段和受控网页中抽取证据，去重后计算 evidence hash 并由系统统一分配引用编号，避免模型伪造来源。将最终回答拆分为原子结论，建立 claim→citation 映射，检查非法引用、数值/单位不一致、文本支持度不足和结论无证据等问题。引用缺失时触发一次受限修复，严重不一致时删除结论、明确降级或附加人工复核提示，并将证据、结论及校验状态持久化。

- **输出契约与多形态交付：** 支持文字回答、结构化 JSON、统计图表及 PPTX 等多形态结果，并将“用户要求什么”与“Agent 实际交付了什么”进行结构化比对。对文件产物校验文件存在性、大小、格式和页数；当用户明确要求图表或 PPTX 时，纯文字回答不能冒充任务完成。产物未生成或证据不满足时，任务进入修复、边界化交付或失败状态，不向前端发布虚假完成事件。

- **权限与数据安全：** 将用户身份、角色、数据范围和允许工具快照绑定到任务，由后端签发短时 HMAC 执行令牌，Agent 执行全程继承同一权限边界。生产模式默认移除 Bash、文件任意写入和未授权子任务等高风险能力；未授权工具不仅无法执行，也不会出现在工具搜索和候选列表中，防止能力与数据 Schema 泄漏。

- **异步任务与高并发调度：** 将长耗时 Agent 执行封装为异步 Job，前端通过 SSE 获取 queued、admitted、running、tool use、telemetry、final 等实时事件。基于 Redis Streams 和持久化 Outbox 进行可靠派发，使用成本感知 DRR 公平调度防止大任务或单一用户独占资源；通过幂等键、会话锁、心跳租约、execution/fencing token、状态迁移校验、断线续传和过期 Worker 结果阻断，保证同一会话不并发污染、任务可恢复且旧执行者不能覆盖新状态。

- **可观测、评测与发布闭环：** 统一记录 Trace ID、任务路由与原因、候选工具变化、模型调用、Token、工具 attempt、资源池、耗时、返回状态、证据、结论、异常和数据访问审计，支持从最终回答反查到具体路由决策、工具输入和数据来源。建设分层评测集，覆盖任务路由、模型/工具选择、SQL 正确性、RAG Recall@K/MRR、并行批处理、引用完整性、证据忠实度、数值一致性、产物完整性、任务完成率、延迟与成本；发布门禁对安全、越权、路由、RAG、引用和任务成功指标执行 fail-closed 校验，防止 Prompt、模型、工具或检索策略变更静默降低系统质量。

## 已完成的真实链路验证

- 通过前端真实发起单车属性查询，验证从 Job 创建、路由、工具调用、证据回写到 SSE Final 的完整链路；高置信任务命中确定性快速路径，仅调用一次专用属性工具完成交付。
- 通过前端真实发起多字段目录查询，验证同类只读工具自动组批、Batch 执行、证据汇总和最终引用交付。
- 通过真实 MySQL 完成受控 SQL 到图表生成链路验证，查询结果携带 evidence hash，图表使用真实数据点生成。
- 通过真实前端调试发现多实例调度与进程内队列边界不一致导致任务长期 queued 的问题，完成调度边界修正、持久化状态刷新和重复派发防护，修复后任务状态按 queued→admitted→running→tool use→final 正常流转。
