## 汽车底盘竞品数据智能管理平台｜项目负责人 / 核心开发

面向底盘研发场景，独立负责平台从业务调研、数据标准与模型设计、后端开发到推广运营的全流程建设，并在统一数据底座上研发可调用结构化数据与专业文档的分析 Agent；形成覆盖约 10 个底盘系统、数百类零部件的数据治理与智能分析能力，服务对象为约 1,400 人的底盘研发组织。

### 一、竞品数据治理平台

独立负责平台从业务调研、数据标准与模型设计、系统开发到推广运营的全流程建设，将底盘工程知识转化为可执行的数据模型、质量规则和平台能力，形成覆盖约 10 个底盘系统、数百类零部件的竞品数据治理体系，面向约 1,400 人的底盘研发组织提供统一竞品数据服务。

- **数据标准与元数据治理：** 梳理“整车—系统—零部件”数据资产体系，制定竞品零部件统一编码、属性、单位及拆解采集标准；针对不同零部件属性差异，基于 EAV 模型建设动态元数据架构，统一管理字段描述、数据类型、值域和小数精度，支持零部件编码自动生成以及零部件、属性模型的在线维护与持续扩展。
- **数据采集与质量管理：** 建立拆解数据模板化采集、字段映射、批量导入、在线校验与编辑流程，从完整性、规范性、一致性及参数偏离度等维度识别异常数据；累计治理并沉淀 120+ 车型、3 万余条竞品数据。
- **数据资产与服务建设：** 建设竞品数据资产目录及结构树，支持按车型、系统、零部件逐级检索，以及编码、名称和动态属性组合查询、数据看板和多车型参数对比；通过个人业务库向用户授权分发竞品数据，支持与本品数据隔离融合开展专题分析，并沉淀约 2,000 条拆解分析与改进提案。
- **数据安全与运营落地：** 建立“管理员—系统负责人/数据维护员—普通用户”三级权限体系，按角色、功能及底盘系统数据范围实施访问控制；由约 10 名系统负责人兼职承担各专业域数据维护，完成中心门户上线、操作培训及跨部门推广，推动数据标准和平台能力在研发业务中落地。

### 二、竞品数据分析 Agent

针对传统 RAG 问答只能根据文档片段生成答案、难以完成结构化数据查询和统计分析的问题，在竞品数据平台基础上整合数百份调研报告、拆解报告及用户手册，构建能够自主取数、检索知识、调用分析工具并输出可追溯结论的竞品数据分析 Agent。

- **Agent Loop 与模型/工具路由：** 围绕“模型决策—工具执行—结果回写—继续推理”构建多轮执行循环，根据任务类型、复杂度、上下文规模及模型可用性进行路由；简单参数问题优先属性直查，复杂任务按需组合 Schema 探查、只读 SQL、RAG 和分析工具，并通过调用预算、重复结果检测、失败熔断及低收益终止控制执行过程。
- **结构化数据分析与 RAG：** 以平台数据库作为车型参数、统计结果和对比数据的事实来源，封装动态属性查询和受控 SQL 工具，支持筛选、聚合及多车型对比；针对非结构化资料建设混合检索 RAG，采用 BM25、字符 TF-IDF 与 RRF 融合召回，结合车型、系统、文档类型等元数据过滤及 Search/Fetch 两阶段检索，为分析结论补充设计背景和专业依据。
- **引用标注与幻觉控制：** 由 Harness 从 SQL 结果快照和 RAG 文档片段中提取证据、去重并分配引用编号，在生成答案前建立“结论—证据”映射，校验引用有效性、数值和单位一致性以及证据支持关系；对证据缺失或来源冲突的结论执行修复、降级或明确拒答，提升结果准确性与可追溯性。
- **上下文工程与执行安全：** 基于 Token 预算自动压缩长会话，分层保留用户约束、任务状态、关键数据和引用关系，将大体量工具结果外置为证据句柄；按用户角色、数据范围和任务场景下发最小工具集，并通过只读数据库账号、SQL AST 校验、表字段白名单、查询成本限制及敏感字段脱敏控制 Agent 的数据访问边界。
- **并发调度与任务可靠性：** 将长耗时 Agent 执行封装为异步任务，基于 Redis Streams、成本感知公平调度及模型/SQL/RAG/工具分级限流实现削峰和背压；通过幂等键、分布式会话锁、心跳租约、失败重试、断线续传及事件持久化保障多用户场景下的执行一致性和故障恢复。
- **评测与可观测性：** 建立覆盖 SQL 正确率、工具路由、任务完成率、RAG Recall/MRR、引用完整性及证据忠实度的回归评测集；统一记录模型调用、工具链路、Token、延迟、异常和数据访问审计，并以 SLO、灰度发布和自动回滚控制版本质量。

**技术栈：** Python、FastAPI、MySQL、SQLAlchemy、Redis Streams、React、EAV、RBAC、RAG、SSE、OpenTelemetry
